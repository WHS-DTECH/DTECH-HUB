Teacher planning reference

Overview

Students express, follow and test algorithms, recognise patterns and create purposeful computational solutions. Year 7 emphasises clear sequences and pattern recognition. Year 8 adds algorithm comparison, responsive programs, debugging and tests of individual parts and overall behaviour.

This school pathway organises part of Digital Technology. It is not a separate official strand, a student task checklist or evidence that the whole strand has been taught.

Year 7 and Year 8 Knowledge and Practices

Read across each common topic. Related themes do not imply identical requirements in both years. Paraphrased curriculum summaries: p. 17.

Programming and algorithms: aligned Year 7 and Year 8 expectations
Common topic and pathway fitYear 7 Knowledge and PracticesYear 8 Knowledge and Practices
Representing and comparing algorithms
Core focus

Knowledge: Algorithms can be expressed, followed and checked using everyday language, diagrams or block/text programming.

Practices: Represent and test simple algorithms with clear ordered steps in those forms.

Knowledge: Different algorithms can solve one problem. Efficiency concerns how step counts or memory requirements change as inputs become larger.

Practices: Compare solutions by counting their steps on inputs of increasing size.

Patterns and repetition
Related progression

Knowledge: Recognising repeated features can simplify problems and support algorithm development.

Practices: Identify patterns in computational-thinking activities and examine their effect on the activity.

Knowledge: Iteration is one of the constructs used in simple programs.

Practices: Use repetition when building and debugging responsive programs. This is a programming application of repetition, not a separately stated Year 8 pattern-recognition requirement.

Input, data and responsive programs
Systems and data connection

Knowledge: Digital systems combine inputs, processing, outputs and data to serve users.

Practices: Examine these relationships in familiar systems. Page 17 does not separately require Year 7 variables, selection and iteration.

Knowledge: Programs combine variables, input/output, sequence, decisions and loops. Systems represent data as text, numbers, images and Boolean values.

Practices: Build and debug programs that respond to input or changing conditions; analyse how data is represented or used.

Testing and debugging
Core focus

Knowledge: An algorithm can be followed and tested through a clear representation.

Practices: Check simple sequences by following them and testing their behaviour. Formal unit and functional testing are not separately specified for Year 7 here.

Knowledge: Unit tests check individual program parts; functional tests check whether the whole program meets requirements.

Practices: Debug programs and check both component behaviour and overall functionality.

Purposeful digital outcomes
Shared requirement

Knowledge: Digital outcomes are developed for a purpose; media design supports an identified audience.

Practices: Design and make an authentic digital outcome suited to its intended use.

Knowledge: Testing and evaluation inform whether a digital outcome meets requirements.

Practices: Design and make a purposeful digital outcome. Where media is included, refine it using audience feedback and design conventions.

Design, Make, and Innovate

Apply the shared design process to a program that meets a genuine need. Paraphrased knowledge and practices: p. 13; integration: p. 17.

Shared design expectations in a programming context
Common themeYear 7Year 8
Purpose, users and process

Knowledge: Frameworks organise design; outcomes may affect different users differently.

Practices: Use a guided process to examine solutions and adapt a brief through work with potential users.

Knowledge: Context, culture, needs and constraints influence design priorities.

Practices: Justify decisions and trade-offs, revisiting them as feedback or evidence changes.

Specifications and testing

Knowledge: Broad attributes describe fitness for purpose; measurable criteria make them testable.

Practices: Develop simple specifications and evaluate attributes, explaining choices.

Knowledge: Specific criteria support reliable testing; modelling helps explore ideas before final production.

Practices: Develop against specifications and test the outcome's feasibility. A program prototype is a suggested classroom modelling context, not a named curriculum example.

Impacts and AI

Knowledge: Technology has intended and unintended effects; everyday AI responds to data and inputs.

Practices: Evaluate impacts of an existing outcome and investigate AI's effects on users.

Knowledge: AI outputs depend on data and instructions and may create benefits or risks.

Practices: Weigh effects on people, communities and environments when choosing how to use AI.

Across both years: apply safe digital work, protection of personal information and ethical, cultural and social responsibility (pp. 13 and 17). If AI assists with code, collect evidence of the student's own explanation and testing rather than treating generated code as proof of understanding.

Learning Contexts

Existing kit connections - not programming coverage

Minecraft Builder Kit offers building instructions and repeated structures that could be adapted into algorithm or pattern investigations. Its current building outline does not require coding, algorithm-efficiency comparison or program testing.

Search Kit can support research into examples and user needs. Searching for a solution is not evidence of writing or understanding a program.

Future activities - proposed, not yet added

  • Unplugged route planner: represent two routes and test their steps; for Year 8, compare step counts as the route problem grows.
  • Pattern-to-loop challenge: identify repeated construction steps, then implement a loop in a suitable block or text language.
  • Responsive quiz or simulation: build a purposeful program using variables, input/output, decisions and repetition, and explain the data used.
  • Testing workshop: check one program part in isolation and test the whole program against its brief; record faults and retests.

Teacher Notes

Curriculum coverage

Map algorithm representation and pattern recognition to Year 7; map comparison, responsive programming and unit/functional testing to Year 8 (p. 17). Use shared contexts while recording the student's actual year level and the specific evidence produced.

Gaps to plan for

  • No dedicated programming task is added by this page. Existing kit completion does not establish the programming expectations.
  • Counting steps on one small input is not the same as comparing growth across increasing input sizes.
  • Running a program once does not show isolated component tests or a check of all intended functionality.
  • Media accessibility, data analysis and responsible use may need separate prompts or links to other pathways.

Possible evidence - teacher judgement required

Collect algorithm diagrams, traces, pattern explanations, annotated code, test cases, expected/actual results, debugging records and evaluations against the brief. Ask students to explain decisions and distinguish supported work from independent understanding.
