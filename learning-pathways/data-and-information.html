Teacher planning reference

Overview

Students investigate how data contributes to a digital system and how information is communicated to an audience. Year 7 emphasises input/process/output relationships, purposeful media and file organisation. Year 8 explicitly identifies different data forms and asks students to analyse their use or representation and refine media from audience feedback.

Spreadsheets, graphs, collecting information and finding patterns are useful school learning contexts. They are not separately named Year 7/8 requirements on page 17 of the supplied Technology document.

Practices: Refine media using feedback and evaluation against conventions.

Files and presentation
Supporting practice

Knowledge: Responsible work includes appropriate handling of files and data; layout and readability affect understanding.

Practices: Apply conventions for file naming/organisation, fonts, colours and layout in simple media.

Knowledge: Responsible management of files, data and personal information applies across the strand.

Practices: Improve media against conventions and audience feedback. There is no separate Year 8 file-naming practice on this page.

Data in programs
Programming pathway connection

Knowledge: Inputs and data contribute to a system's operation.

Practices: Investigate a familiar example. Variables and Boolean program decisions are not separately specified for Year 7 here.

Knowledge: Simple programs use variables, input/output, sequence, decisions and iteration; Boolean values are a data form.

Practices: Build and debug responsive programs and analyse their data. Map the programming evidence separately rather than assuming a spreadsheet provides it.

School-context extensions: surveys, spreadsheets, charts, data accuracy checks and interpretation of patterns may support these expectations. Page 17 does not explicitly prescribe them, nor binary encoding or a statistics sequence.

Learning Contexts

Existing kit connections

  • Search Kit: the visible search activities support finding information and refining queries. Add an explicit task analysing how information is represented or used; retrieval alone is not data analysis. Hidden source-credit and verification activities are not assumed to be available.
  • Minecraft Builder Kit: Camera, Portfolio and export provide image and file contexts. Add annotations explaining the information represented, the intended audience and file organisation.
  • Login Kit: school accounts and Drive setup support accessing and storing work. Signing in does not show data-representation understanding.

Future activities - proposed, not yet added

  • Build-data investigation: use fictional or non-sensitive building measurements to compare numerical data, labels, images and Boolean checks.
  • Spreadsheet-to-information outcome: organise a small dataset and choose a clear presentation for an audience; explain the representation rather than only formatting cells.
  • Audience-tested information guide: gather feedback on readability and accessibility, then record justified changes.
  • Data-use detective: trace where data enters a familiar system and how it is processed and communicated.

Teacher Notes

Curriculum coverage

Direct links are system/data relationships, Year 8 data forms and analysis, purposeful media, design conventions and responsible file management (p. 17). Spreadsheet and graph work is a selected teaching context, not a quoted requirement. Record actual year level and avoid double-counting one screenshot as evidence of every connected pathway.

Gaps to plan for

  • Finding answers or exporting images does not itself demonstrate analysis of data representation.
  • Year 8 audience feedback and refinement need deliberate prompts.
  • Personal-data protection, relevant cultural responsibilities and choices about sharing should be explained, not inferred from a saved file.
  • Algorithms, programming and statistical concepts need their own teaching and mapping where included.

Possible evidence - teacher judgement required

Collect annotated data examples, system diagrams, organised files, audience-focused information outcomes, feedback and explained revisions. A spreadsheet can support evidence when the student explains what its data means and why the representation suits its purpose.

No grades, progress descriptors or automatic curriculum-completion rules are assigned here. Check the eventual official curriculum before treating the mapping as a compliance reference.
